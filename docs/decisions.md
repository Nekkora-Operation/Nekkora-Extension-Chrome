# Registro de decisões

| ID | Decisão | Alternativas consideradas | Justificativa / evidência |
|---|---|---|---|
| D-001 | **Native Messaging** como canal Chrome ↔ Java | servidor Java em `127.0.0.1` | sem porta aberta, sem CORS, processo iniciado pelo próprio Chrome e restrito à extensão autorizada (`allowed_origins`); fragmentação implementada e testada (C-2, C-3); reconexão testada (C-5) |
| D-002 | Regras de análise **somente em Java**; JS restrito a APIs do navegador | motor em JS/TS | requisito da missão; motor testável sem navegador (113 testes unitários) e reutilizável pelo Studio |
| D-003 | Extensão em **JavaScript puro**, sem bundler | TypeScript + build | elimina etapa de build e dependências; content scripts clássicos compartilham um namespace; testes com `node --test` sem pacotes |
| D-004 | **Maven** multi-módulo com wrapper | Gradle | mesma convenção do Nekkora-Studio (`com.nekkora`, `mvnw`); Maven já em cache local |
| D-005 | Testes de navegador com **Chrome for Testing** via Selenium | Chrome de marca | Chrome de marca ignora `--load-extension` desde a 137; CfT tem versão fixa e baixável (`ChromeForTesting`) |
| D-006 | **Arquivos JSON** locais; sem PostgreSQL | PostgreSQL + Docker | nenhum requisito desta fase exige consultas relacionais; registro de alvos, PageMaps e evidências cabem em arquivos; testes rodam sem banco. Reavaliar quando o Studio consumir histórico multi-sessão |
| D-007 | Destaque por **overlay independente** (shadow root fechado) | `outline` inline no elemento | não altera estilo/layout (verificado em T034: retângulo e estilo do alvo idênticos antes/depois), não contamina a captura (overlay excluído) e acompanha re-renderização |
| D-008 | **Id fixo** da extensão por chave pública no manifesto | id variável de carga não compactada | `allowed_origins` previsível; o instalador calcula o id a partir da chave (sem digitação); chave privada não versionada |
| D-009 | Registrar host em `HKCU\Software\Google\Chrome` e `HKCU\Software\Chromium` | incluir `Software\Google\Chrome for Testing` | verificado experimentalmente: o CfT 155 **não** lê `Google\Chrome for Testing`, lê `Chromium` (registro somente CfT → `HOST_UNAVAILABLE`; somente Chromium → sucesso) |
| D-010 | **Licença não definida**: "todos os direitos reservados" até decisão da Nekkora | MIT / Apache-2.0 | a missão pede avaliação antes da publicação; a biblioteca de referência é `UNLICENSED`. Decisão pertence à Nekkora |
| D-011 | Valores de campos nunca exportados, exceto **campos de pesquisa** | exportar todos / nenhum | permite distinguir "consulta realizada pela interface" (§14) sem expor dados pessoais; sensíveis bloqueados em duas camadas (T033) |
| D-012 | Mutações por **deltas incrementais** encadeados | recaptura completa a cada mutação | requisito de desempenho; 513 mutações → 7 deltas, máx. 7,6 ms no host (T037) |
| D-013 | **Discriminadores** calculados no registro contra elementos parecidos | comparar somente com o seletor | evita confundir botões idênticos em linhas/tabelas/formulários diferentes; um alvo indistinguível no registro nunca é resolvido depois (T032) |
| D-014 | Chaves estruturais (formulário, grupo, tabela, diálogo, título) comparadas **estritamente** | similaridade de tokens | "Endereço de cobrança" × "Endereço de entrega" tinham similaridade parcial; identidade não admite semelhança parcial (teste `billingStateIsNotShippingState`) |
| D-015 | Ids/names com aparência dinâmica têm estabilidade **reduzida**, nunca rejeitada | descartar ids "aleatórios" | requisito §11; estabilidade comprovada por observação (`OBSERVED_*`) prevalece sobre heurística (T005) |
| D-016 | Hooks de teste: lista fechada, somente leitura, marca `__nekkoraLab`, só em origem local, via `chrome.scripting` no mundo da página | percorrer `window` | requisito §15.2; função com efeito colateral fora da lista comprovadamente não executada (T038) |
| D-017 | Harness e página em **janelas separadas** nos testes, sem estrangulamento por oclusão | abas | abas em segundo plano suspendem `requestAnimationFrame` e estrangulam timers, invalidando medições de responsividade e acompanhamento do destaque |

## CHROME-002

| ID | Decisão | Alternativas consideradas | Justificativa / evidência |
|---|---|---|---|
| D-018 | Separar **CaptureSession** (por aba, com consumidores) de **InspectionSession** | uma única "inspeção ativa" | desativar a inspeção não pode encerrar uma gravação; a gravação futura é só outro consumidor (C002-049) |
| D-019 | **Deltas sequenciados** `{sessionId, source, epoch, seq}` validados pelo motor Java | confiar na ordem das mensagens; base por `baseCaptureId` | recusa explícita de deltas antigos, lacunas e documento trocado sem alterar o estado confirmado; ressincronização controlada (C002-017) |
| D-020 | Captura-base **cooperativa** (fatias de 8 ms, partes de 1.000 nós com confirmação) + política **BASE_PLUS_DELTA** | captura síncrona; snapshot "instantâneo" | bloqueio contínuo 10k: 359 → 22 ms; mutações durante a travessia ficam no 1º delta (C002-039). Não se declara instante único |
| D-021 | Seleção usa a **barreira de sincronização** + captura fixada (`capture.pin`) | captura completa por clique | 10 seleções = 1 captura completa (C002-011); seleção 10k: 350 → 79 ms |
| D-022 | **Referência fixada** fora do LRU (3 capturas + 1) no motor | aumentar o LRU | cada delta gera uma captura; comparação precisa da base sem reter capturas ilimitadas (MAX_CAPTURES reduzido de 6 para 3) |
| D-023 | Iframes de outra origem permitida por **content script no próprio frame** (`all_frames`) + handshake `postMessage` com token | ampliar permissões; CDP | sem novas permissões; uma fonte por documento (sem duplicidade); sandbox não anexado por política (C002-029..032) |
| D-024 | `attachShadow()` tardio detectado por **reconciliação periódica (1 s)** | monkeypatch de `attachShadow` no mundo da página | missão proíbe monkeypatch indiscriminado; latência medida ≈ 1,07 s (C002-028) |
| D-025 | Exportação **na finalização da gravação**, idempotente por `operationId = recordingId`, escrita em fluxo + `.tmp` + movimento atômico + SHA-256 + validação | exportar ao desativar a inspeção; download | "exportar" ≠ download; falhas não memorizadas; 10k: 2.411 → 1.070 ms (C002-022..025, C002-038) |
| D-026 | Modo **DEV/PRD definido pela construção** (`build-mode.js`; `build.ps1 -Mode PRD`) com simulação de PRD apenas por páginas da extensão em DEV | modo escolhido pela página / por opção do usuário | a página nunca altera o modo; DEV tools removidas do DOM em PRD e recusadas no service worker (C002-048) |
| D-027 | **Geometria** atualizada em rolagem/redimensionamento e na barreira de exportação | recaptura periódica; ResizeObserver em todos os nós | deslocamentos de layout não são mutações DOM; equivalência incremental × completa sem recapturar (C002-045) |
| D-028 | `textSegments` opcional no snapshot bruto para conteúdo misto | manter `ownText` agregado | corrige a ordem texto/elemento do AccName ("Mostrar 20 itens"); campo aditivo, snapshots antigos mantêm o comportamento anterior |
| D-029 | Homologação no **Chrome convencional** por CDP `Extensions.loadUnpacked` + ChromeDriver anexado (`debuggerAddress`) | somente Chrome for Testing | o Chrome de marca ≥ 137 ignora `--load-extension`; perfil temporário, só laboratório local (BrandedChromeIT) |
| D-030 | Painel lateral **nativo** homologado por `chrome.runtime.getContexts(SIDE_PANEL)` + estado lido do próprio painel + captura de tela do SO | testar a página do painel como aba | o side panel não é janela do WebDriver; a aba continua usada só como harness (C002-047) |
| D-031 | Iframe "sem permissão" do laboratório em **127.0.0.2** (escuta adicional do LabServer) e segunda origem permitida na **porta +1** | usar `localhost` como origem inacessível | com `all_frames`, `localhost` passou a ser origem permitida e inspecionável; T020 (captura avulsa, sem sessão) continua válido sem alteração |
| D-032 | Barreira declara `SYNCHRONIZED` somente com confirmação de **todas** as fontes obrigatórias; senão `INCOMPLETE` com `unconfirmed` | tratar erro de flush como "sem pendências" | revisão do PR #1: um erro de comunicação podia resultar em sincronização presumida (C002-R01) |
| D-033 | Finalização FINAL exige `SYNCHRONIZED` (navegador e motor); exportações incompletas ou de diagnóstico são `PARTIAL`, em arquivo distinto, nunca memorizadas | memorizar qualquer `EXPORTED` | revisão do PR #1: uma exportação `complete=false` podia ficar permanentemente confirmada (C002-R02) |
| D-034 | Gravações persistidas em `storage.session`; eventos de uma gravação serializados; retenção só de registros encerrados | `Map` em memória com limite FIFO | revisão do PR #1: reinício do service worker perdia a gravação; cancelamento disputava com finalização; o limite podia descartar gravações ativas (C002-R03/R05/R06) |
| D-035 | Alvos com **dono** (aba + sessão de captura) no registro do motor; exportação filtra pela sessão; reencontro automático filtra pela **sessão do delta**; reencontro explícito exige a **aba dona** (`TARGET_NOT_OWNED`) | filtrar por URL; reencontro automático por aba | revisões do PR #1: duas abas na mesma URL podiam misturar identidades (C002-R04); uma aba podia resolver/atualizar a identidade de outra e alvos de sessões encerradas participavam do reencontro automático (C002-R07/R08). Registros antigos sem dono podem ser resolvidos mas nunca são atualizados nem exportados em sessões |
| D-036 | Caminho do arquivo exportado decidido **pelo resultado efetivo**: completo → `session-<s>-<op>.json`; parcial (truncado ou diagnóstico) → `…-partial-<instante>-<n>.json`, único e nunca sobrescrito | sufixo conforme o modo solicitado | segunda revisão do PR #1: uma exportação normal truncada recebia o caminho do arquivo completo e podia ser sobrescrita (`truncatedFinalExportIsPartialAndNeverOverwritten`) |

## CHROME-003

| ID | Decisão | Alternativas consideradas | Justificativa / evidência |
|---|---|---|---|
| D-037 | PageMap **0.2.0** com seções aditivas (`frameGraph`, `accessPaths`, `protection`, `readiness`, `elements[].documentId`); 0.1.0 arquivado em `contracts/v0.1.0/`; asserções de versão das ITs/unitários atualizadas | manter 0.1.0 com campos novos | o schema usa `additionalProperties: false`: campos novos tornam o documento inválido no 0.1.0, logo é nova versão (§24). Removidos os campos aditivos, o PageMap 0.2.0 valida no schema 0.1.0 (F003-020) |
| D-038 | Identificadores do Chrome (`frameId`, `documentId`) em `BrowserFrameMetadata`, **separados** dos ids lógicos; associação somente por `TOP`, `HANDSHAKE` ou `URL_MATCH` (URL única sob o mesmo pai) | associar por ordem/posição; usar `frameId` como identidade | §5.2/§7.2: nada inventado (campos ausentes = `null`); `frameId` muda a cada recriação (F003-002, testes unitários de associação) |
| D-039 | Handshake de frames resolvido no **dono da captura** do pai (anúncio a todos os ancestrais) | consultar sempre o pai imediato | em cadeias de mesma origem o pai imediato tem registro próprio: o `hostNodeId` não coincidia com o estado do motor (frames de 2º nível ficavam sem `documentId`) |
| D-040 | `ELEMENT_BELONGS_TO_DOCUMENT/FRAME` emitidos para elementos **estruturais** (hosts de iframe/shadow); pertença dos demais em `elements[].documentId` | uma relação por nó | 10.000 nós ⇒ 20.000 relações sem informação nova; o grafo continua navegável (F003-001) |
| D-041 | **Não** habilitar `match_about_blank`/`match_origin_as_fallback` | injetar em about:blank/srcdoc | esses documentos já são capturados pelo pai via `contentDocument`; uma segunda fonte duplicaria a captura (§8). Metadados do Chrome associados por URL única (F003-012/013) |
| D-042 | Troca de documento de iframe de mesma origem detectada por `load` (captura) + verificação periódica do `contentDocument`; recaptura **só do iframe** | recaptura completa; `webNavigation` apenas | navegação interna não gera mutação no pai; o rastreador não via o novo documento (F003-003/017/018 falhavam) |
| D-043 | Limite de frames por aba conta só frames **anexados** (fonte própria) | contar todas as entradas | frames de mesma origem só fazem handshake; acima de 20 perdiam o `documentId` do Chrome (D003-001 com 30 frames) |
| D-044 | Detector de proteções **passivo e determinístico** sobre catálogo versionado (`protection-signatures.json`), com base (`OFFICIAL_DOCUMENTATION` × `THIRD_PARTY_OBSERVATION`) e teto de confiança por assinatura | heurística livre; IA; consulta a serviços externos | §11/§16: explicável e revisável; terceiros nunca `HIGH` (`SignatureCatalog.validate`) |
| D-045 | Confiança por **canais independentes** (RESOURCE × DOM × DOCUMENT), com teto, conflito e **sombreamento** (assinatura menos específica do mesmo fornecedor perde um nível) | contar evidências | um script sozinho não prova widget; `api.js?render=` é v2 explícito ou v3 e o valor não é coletado (P003-008) |
| D-046 | Estados de desafio exigem sinal explícito; só evidência fraca ⇒ `UNKNOWN`; conclusão só com campo de resposta preenchido; desaparecimento ≠ conclusão | inferir pelo DOM visível | §13/§18 (P003-002, P003-010, P003-011) |
| D-047 | Fixtures com scripts `type="application/x-nekkora-inert"` e `data-nekkora-simulated-src` | chaves de teste reais dos fornecedores | §17: nenhum serviço real, nenhuma chave real, nenhum tráfego; evidências marcadas `simulated` (P003-013 confere Resource Timing só local) |
| D-048 | Valores de parâmetros de `src` de iframe/script e do atributo simulado redigidos na captura (`k=REDACTED`), `data-sitekey` = `[redacted]` | exportar URLs completas | §12: chaves/tokens nunca coletados; nomes de parâmetros mantidos para a análise (P003-013) |
| D-049 | Proteção `POSSIBLE` (LOW) vira `UNKNOWN_PROTECTION` + `MANUAL_VALIDATION` na prontidão | tratar como verificação humana | evidência fraca não deve exigir intervenção humana (P003-011) |
| D-050 | Diagnóstico exposto por `page.diagnose` (resumo sem PageMap) com barreira + metadados atualizados antes; painel com atualização limitada (≤ 1 a cada 2 s) | calcular no painel; enviar PageMap | regras no Java (§33); o painel não recebe PageMap para atualizar contadores (CHROME-002) |
| D-051 | Comparação de desempenho com o baseline usando **o mesmo procedimento** do C002-038 | medir em página recém-aberta | a primeira medição (sem captura prévia) mostrava 2× por aquecimento de layout/JIT, não por regressão (reports/chrome-003/performance.md) |
